# music-video-maker

Turn a song into an audio-reactive music video. Upload an MP3 and lyrics, describe the song (meaning, genre, mood),
and get an MP4 whose visuals are generated entirely in code and driven by the audio. A per-project toggle switches
between a **lyric video** and a **visuals-only** video.

1. **Analyze** the audio: tempo, beats, sections, loudness/bass/treble, notes.
2. **Align lyrics** to the vocals (Demucs isolates the vocals, Whisper aligns your words, then stable-ts refines each word's start (a word keeps the end it was aligned with, since refining clips held notes); refining is the slowest step, roughly 3 minutes extra for a 4-minute song on CPU) and fix the timing in a waveform editor. Export `.lrc` / enhanced `.lrc`.
3. **Style plan**: Claude turns your song details, structure and lyrics into a per-section plan (visual, intensity, palette, camera, lyric animation, transition). Edit anything, tune per-section parameters, or regenerate a single section.
4. **Storyboard** (optional): Claude designs a cast and one scene per section (setting, time of day, weather, props, characters with their actions and expressions), drawn as flat, stylized illustrations with simple faces, either from the built-in library or as free-form SVG that Claude draws. Edit anything or regenerate a single scene.
5. **Preview** live in the browser, then **render an MP4** (16:9, 9:16 or 1:1).

## Requirements

- Node 22+, [uv](https://docs.astral.sh/uv/) (Python 3.12 is pinned), and `ffmpeg` (`brew install ffmpeg`)
- Optional, for the Blender renderer: Blender 5 (`brew install --cask blender`)
- An Anthropic API key for the Claude steps (style plan, storyboard, free-form art). Each user enters their own under **Claude API key** at the top right; it's kept in that browser's localStorage and sent only with Claude requests. The backend never reads `ANTHROPIC_API_KEY`, `ant auth login` or Claude Code's login
- Disk: first use downloads Demucs `htdemucs` (~80 MB) and Whisper `medium` (~1.5 GB) to `~/.cache`, and the first render downloads Remotion's headless Chrome

## Setup and run

```bash
npm install
(cd backend && uv sync)
npm run dev          # API on :8000 and web app on http://localhost:5173
```

If `uv` is configured with a private package index, add `--default-index https://pypi.org/simple`.
`npm run dev` starts both servers; `npm run dev:api` / `npm run dev:web` start them separately.
Interactive API docs: http://localhost:8000/docs.

## Using it

1. **New project**: choose an MP3, paste lyrics, fill in the song details, optionally *Browse…* for the folder to save in, then *Analyze & align*. A progress bar shows each stage. Without lyrics, or with *Lyric video* off, alignment is skipped.
2. **Lyrics sync**: drag line regions on the waveform. `↑/↓` select a line, `Enter` plays from it, `←/→` nudge 10 ms (`Shift` moves only the start). *Tap-to-sync*: with it on, press `Space` while playing to set the selected line's start. Save, import or export `.lrc` from the same panel.
3. **Sections**: once analysis is done, describe the scene you want for each part of the song. Each section is one scene: *Split* adds a scene (the new part starts as a copy of the one it came from), *Remove* merges a section into its neighbour, and the start time and name are editable. Your style plan, storyboard and descriptions are re-indexed with the edit. Claude follows the descriptions when writing the style plan and the storyboard.
4. **Style plan**: pick the Opus 5.5 effort level, *Generate style plan*, then edit. *Tune* opens per-section sliders and a custom palette; *Regenerate* redoes one section (your palette override is kept).
5. **Storyboard**: set *Visual mode* to `scenes` (illustrations only) or `both` (illustrations over the abstract visuals), then *Generate storyboard*. Edit the cast (gender, hair, outfit, build, colors; characters made before gender was a choice get a guess from their hair and outfit, which you can change) and each scene (setting, time, weather, crowd, props, who does what, where). *Regenerate* redoes one scene. A section with no scene falls back to the abstract visuals.
   - **Illustration** chooses how scenes are drawn: `library` (built-in rigged figures and parametric scenery, no extra cost) or `freeform` (SVG that Claude draws). Each scene can override the default.
   - **Objects** are your own props (a name, a description, a size). Claude places them in scenes, draws each as an SVG when you press *Draw art* (in both `library` and `freeform`), and the renderer draws them over the backdrop. Objects without art are skipped.
   - In `freeform`, *Draw art* has Claude draw a character or a backdrop per asset (a few calls, run in parallel in the background with a progress bar). It only draws what's missing; *Redraw art* / *Redraw backdrop* redo one. Anything that fails or is missing falls back to the library art, so a scene never renders blank.
6. **Export**: *Render MP4* or a 15 s preview. Download the result when it finishes.

**Project files.** Song details, lyrics and settings save automatically a moment after you change them (the style plan and storyboard have their own Save buttons), into the project's folder, which can be anywhere: pick it with *Browse…* when creating a project, or *Save as…* to copy a project (without renders) to a new folder. *Open folder…* adds an existing project folder to the list; the ✕ on a row only removes it from the list. *Export .mvm* writes the whole project as one file (a zip of the project files, no renders) and *Import .mvm…* unpacks one into a folder you choose, under a new id. The list of known folders is kept in `projects/.registry.json`.

## How it works

Every frame is a pure function of `(frame, analysis, lyrics, plan, settings)`. Audio features are computed once at the video frame rate, so the browser preview and the exported MP4 match frame for frame, and renders are reproducible (randomness is seeded).

| Path | What |
|---|---|
| `backend/` | FastAPI + Python: analysis (librosa), vocal separation (Demucs), alignment (stable-ts / Whisper), LRC, style plan (Claude), background jobs, render runner |
| `video/` | Remotion composition: abstract presets, scene illustrations (`src/scenes/`), lyric layer, transitions, `render.mjs` (MP4 export) |
| `web/` | Vite + React editor that embeds the Remotion `Player` |
| `shared/` | `schema.json` generated from the Pydantic models, and the TypeScript types generated from it |
| `projects/<id>/` | Default location for project files (git-ignored; projects can live elsewhere): `audio.mp3`, `project.json`, `analysis.json`, `lyrics.json`, `style_plan.json`, `storyboard.json`, `vocals.wav`, `out/` |

Only one heavy job (analysis/alignment or a render) runs at a time; a second request returns `409`.

## Development

```bash
cd backend && uv run pytest        # backend tests
npm test                           # video tests (vitest)
npm run typecheck -w web           # also: -w video
npm run schema                     # after changing backend/app/models.py: regenerate shared/ types
```

**Scenes**: characters are a fixed 2D rig (`video/src/scenes/rig.ts`) posed by action functions (`actions.ts`); backgrounds, props, sky and weather are parametric SVG. Claude only picks from the allowed vocabulary (the `Literal` types in `backend/app/models.py`), so a storyboard can never name something the renderer can't draw. To add a setting, action or prop: extend the `Literal`, run `npm run schema`, then implement it in `video/src/scenes/` (the build fails until every case is handled where the types require it).

**Free-form art and safety**: SVG written by Claude is untrusted input. It goes through a strict allowlist (`backend/app/svgsafe.py`) when saved, and again in the renderer (`video/src/scenes/safeSvg.ts`), which rebuilds React elements from an allowlisted tree and never injects markup. Scripts, event handlers, `foreignObject`, external links and images, CSS and animation never survive. Both implementations pass the same malicious samples in `shared/svg-fixtures.json`, so change them together. Drawing conventions the prompts rely on: figures use `viewBox="0 0 100 200"` facing right with named, pivoted parts (`head`, `arm_r`, `forearm_r`, `leg_l`, `shin_l`, ...) that the pose engine rotates, and backdrops use `viewBox="0 0 1600 900"` with the ground line at y=693. A figure without parts still moves as a whole.

**Looks and motion**: the style plan's `look` is `clean` or `riso`. `riso` wraps the whole frame in a print finish (`video/src/riso/`): channel misregistration of 1-3 px, static paper grain and mottling, a dot screen and specks, all fixed in place (they never flicker) and seeded from the song, replacing the film grain and vignette; it also writes the title card with a pen. The `ripples` (a centre dot, a hand-drawn ring per beat, and a lens ring that tightens on each downbeat), `halftoneBloom` and `orbits` presets suit it. Lyric animations `inkStamp`, `dotDissolve` and `handwrite` write words with a second ink, break them into dots, or draw them stroke by stroke with a single-line font (`video/src/strokeData.ts`, Hershey data under its own usage terms, Latin text only; other text falls back to the normal font). **Lyric timing** (`video/src/timing.ts`): a line starts appearing before it is sung (1 s after a gap of 2 s or more, else 0.5 s, never before the previous line ends, 0.15 s when lines run on), and the styles that reveal words as they are sung (`pop`, `kinetic`, `inkStamp`, `dotDissolve`, `typewriter`, `handwrite`) start each word 0.15 s early so it has landed by its beat; `karaoke` shows the whole line ahead and highlights as it is sung. Transitions are in `video/src/transitions.ts` and cameras in `Camera.tsx`.

**Blender renderer** (`blender/`): *Renderer* in the song details switches export between Remotion (the flat 2D look above, with the live preview) and Blender (realistic 3D), per project. Blender does it its own way rather than copying the 2D look: it builds one 3D scene from the same analysis, lyrics, storyboard and style plan, with procedural settings for `road`, `city`, `field`, `room`, `shore`, `forest` and `void`, a physical sky and sun for the time of day, fog, a 3D figure per cast member, and 3D lyric text. Each figure is one skinned body (torso, neck, arms and legs weighted to an armature, so joints bend smoothly) over a head with a skull and jaw, eyes with lids, nose, lips and ears, with skin and cloth materials and hair grown as hundreds of tapered locks (`mvm/hairgen.py`: a crown whorl for short cuts with a parting, long hair that frames the face and hangs under gravity around the head and shoulders, a bun wound round a ball; glossy, with the colour varying lock to lock); its shape follows the character's *Gender* (broader shoulders and a heavier jaw for male, wider hips, a narrower waist and a bust for female; the Remotion figure's torso follows it too). It reimplements the logic in Python rather than sharing the TypeScript: beat and section timing (`mvm/timing.py`), body motion with a real walking and running journey and hip and shoulder twist (`mvm/motion.py`), and the shot plan with dolly, depth of field and hand-held drift (`mvm/camera.py`). The preview player in the app is still Remotion; Blender renders only on export, so use *Render 15s preview* first. Measured on this machine at 720p: about 0.25 s per frame for the preview clip (16 samples) and about 0.55 s per frame for the full render (48 samples, `MVM_SAMPLES` overrides), so a 4-minute song is roughly an hour. Not covered yet: crowds, moods beyond blinking and singing, and custom free-form SVG art, which falls back to the stock figure. It needs Blender 5 (`brew install --cask blender`, or set `MUSIC_VIDEO_MAKER_BLENDER`).

Weather in Blender is real: rain and snow fall as thousands of drops that follow the camera (`mvm/weather.py`, geometry nodes, each drop a pure function of the scene time, so any frame renders without simulating up to it and motion blur streaks the rain), roads and ground turn dark and shiny in rain and white under snow, and the sun is dimmed under cloud. Rain scenes cost more to render (about 0.4 s per frame at preview quality, against 0.25 for clear ones).

**Lyric fade** (*Lyric fade* in the song details: Hard, Normal or Gentle, per project, Gentle by default): how a line fades in, how long it lingers after its last word, and how it hands over to the next. When the next line begins to appear the old one clears at once (0.1 s hard, 0.22 s normal, 0.5 s gentle) and lifts away, so two lines are never printed over each other; Gentle lifts it further so the slower fade stays separate from the new line. Both renderers follow it (`FADES` in `video/src/timing.ts` and `blender/mvm/timing.py`).

**Title and artist** (*Show title and artist at the start*, on by default per project): in a lyric video the title card holds through the intro, up to 8 s, and fades out just before the first lyric starts to appear (skipped if the lyrics start within about 1.6 s); without lyrics it is a 4 s opening card, plus a closing one in Remotion. Both renderers do it (`video/src/TitleCard.tsx`, `blender/mvm/lyrics.py`).

**Held props and gaze**: in the storyboard each character in a scene can hold something (`holding`: umbrella, suitcase, microphone, flowers, lantern, book, phone, flag, balloon, cup, sword, shield (round, face on, in the character's accent metal), or a guitar played with both hands) and look at someone (`looks_at`: another character in the scene, who they then turn to face, or the camera, which shows a face seen from the front). Claude sets them and they are editable per character in the scene editor. The held item takes over the arm(s) it needs (`video/src/scenes/held.ts`, drawn in `HeldItem.tsx`) and the other arm keeps doing what the action does. On characters drawn as custom art (*freeform* illustration) the item is drawn at the drawing's own hand, found from its `arm_r` and `forearm_r` pivots (`artHand` in `scenes/freeform.tsx`), or at its hip for a guitar; the eyes also track and the lyric moods apply there. Hats, outfits and accessories are part of a drawing, so they only come from the character's art. Blender builds the same items in 3D (`blender/mvm/wear.py`); gaze turns a figure toward the other character, or most of the way round to the camera.

**Wardrobe**: a character can wear a hat (`hat`: cowboy, beanie, cap, top_hat, beret, sun_hat, helmet (an ancient crested warrior's helmet with a cheek guard, nose guard and plume in the character's top colour); worn over the hair, in the character's accent colour), up to two accessories (`accessories`: glasses, sunglasses, scarf, headphones, backpack) and, besides tee, coat, dress and hoodie, a jacket, suit (lapels and tie), overalls or a robe (a long, belted prophet's robe with a sash and long sleeves, down to the ankles, or armor (an ancient warrior's bronze cuirass with the muscles drawn on it, shoulder guards, bracers and greaves over a leather strip skirt; the metal takes the character's accent colour, so it can be bronze, gold or steel) (`video/src/scenes/Wearables.tsx`, `blender/mvm/wear.py`). Scenes have three more props (campfire, fence, signpost). All are editable per character in the storyboard editor.

**Crowds**: a scene's *Crowd* number (0-8 background figures) wins when set, with 0 meaning none on purpose; left empty, the renderer adds 2-6 in intense sections (more as the intensity rises) unless the lead is alone on purpose (sitting, slumped, looking up), and the project's *Background crowds in intense scenes* checkbox turns that off (`scenes/crowd.ts`, `mvm/rules.py`). They turn toward the lead and follow the music: strolling and standing when calm, then swaying, cheering with a raised arm and jumping as the section gets more intense, some in hats. Blender draws up to 6, as dark silhouettes.

**Expressions that follow the lyrics**: Claude sets a mood on the lyric lines where the feeling turns (`moods` in the storyboard, stored by the line's start time so editing line text does not lose them), the lead's face holds it until the next one (at most 8 seconds), and the music's loudness shows it a little bigger or smaller. Set them by hand under *Expressions by lyric line* in the storyboard editor.

**Colour grading**: each section has a `grade` in the style plan (none, warm, cool, faded, noir, vivid, dream; the *Grade* column of the section table), eased from the last section's grade through each change and pushed a little harder by loud music (`video/src/grade.ts`, drawn as a CSS filter and tint under the lyrics; in Blender a compositor chain keyed per frame, `mvm/grade.py`).

**Light that follows the song** (`video/src/scenes/lighting.ts`, `LightFx.tsx`; scenes mode, Remotion): the cast is edged with light from behind that brightens with loudness and on each beat; the whole scene lifts briefly on a beat, more on a downbeat; a lens flare blooms at the sun or moon when something loud hits; and across a section the scene's light drifts about a third of the way toward the next time of day (dusk slowly darkening toward night). All of it shows less in daylight than at night. There are no settings for it; the amounts are constants at the top of `lighting.ts`.

**More life**: four more actions (`point`, an arm out toward the other character or the world; `lean`, which puts the scene's signpost, lamp, tree or fence, or a lamp if there is none, behind the figure and leans them on it; `cross_arms`; `cheer`, both arms up and bouncing on the beat). Eyes track (`scenes/gaze.ts`): toward the other character they look at, following their jumps, level and still when looking at the viewer, and otherwise down when sitting or slumped, up when looking up, with small glances. Rain, snow and fog follow the music (`scenes/weatherMusic.ts`): more drops and thicker fog when louder, and on a hard hit rain leans over and snow is shaken (the gust is Remotion only). **Lyric cues** (`cues` in the storyboard, stored by line start time like moods; set by Claude and under *Expressions, symbols and items by lyric line* in the editor): a symbol (heart, star, rose, key, door, moon, bird, clock) pops up beside the lead for about 2.6 s, and/or the lead is handed an item (any held item) until a later line gives them another, at most 8 s (`scenes/cues.ts`, `Symbols.tsx`). **Costume changes**: a scene's character can wear a different outfit, hat or accessory in that scene only (`wear`; the three selects on the scene's character row, each "usual" by default); Claude uses it where the story passes time or the mood changes.

**Contact between two characters** (`contact` on one character of a pair: a `partner` and a `kind`; the *Contact* selects on the scene's character row): `hug`, `hold_hands`, `high_five` or `arm_around`. The pair stands together at the first character's place (`pairings` in `scenes/layout.ts`): face to face with the first on the left for a hug or a high five, side by side facing the way the first faces, that one ahead, for the others, and they look at each other when face to face. They lean and tilt together and an arm of each is solved with two-bone IK (`armTo` in `rig.ts`, `scenes/contact.ts`) so the hands really meet: round the other's back, joined at hip height, high up, or an arm over the shoulder with the other's hand on the waist. A character is in one pair, and a partner who is not in the scene makes no pair (the backend drops it). Blender solves the same arms in the figure's plane (`mvm/contact.py`) and stands the pair on one line.

**Scenery that moves** (`scenes/scenery.ts`): trees and grass sway harder when it is loud and lean over on a hard hit; lamps and city windows swell on the beat and flicker, more on hits; the campfire's flames get taller and its glow brighter with loudness; sea waves and glints swell. Blender moves its lamps and the campfire the same way (`mvm/rules.py`); its trees, windows and water stay still.

**Lyric tint**: while a cue's symbol is up the lyric line takes the symbol's colour (up to 60%, easing in and out over a fraction of a second), and while a cue's item is in hand it takes the item's colour more gently (up to 30%) (`cueTint` in `scenes/cues.ts`; in Blender the word materials mix it in through drivers on a keyed scene property). The scene's own `holding` does not tint.

**Blender parity**: Blender also gets the held items, gaze, the four new actions, eyes that turn in their sockets, lyric cues (symbols as extruded 3D shapes facing the camera, items shown and hidden on cue), costume changes, rain, snow and fog that thicken with the music (no gust), hats, accessories, outfits, scene props, crowd, expressions (brows, eyes and jaw), the entrance wind-up and overshoot, a rim light behind the lead that follows loudness and beat, a brightness lift on beats, the colour grade, and the time-of-day drift. It has no lens flare, no music-chosen transitions (it cuts between scenes) and no motion-blur setting (it always uses Blender's own).

**Metatags in the lyrics** (`backend/app/lyric_tags.py`): a line like `[scene]`, `[scene 1]` or `[Chorus]` (any bracketed tag at the start of a line, with or without lyrics after it) starts a new song section at the next sung line. The tags are taken out before alignment, so they are never aligned, shown or exported. When Analysis and alignment run with lyric video on, the tags *define the sections*: each tag cuts where the first aligned line after it starts, the tag text is the section's label (a bare `[scene]` is numbered scene 1, 2, ...), and whatever comes before the first cut is its own `intro` section (unless the first tag is right at the start). With no tags nothing changes. Cuts closer than 1 s to another or to the end are dropped (the earlier tag stays), at most 40 sections, and a tag with no sung line after it is ignored. The cuts are left at the lines' starts and snapped to the nearest downbeat when the video is made, like the detected ones, so the sections are not marked as hand-edited. Each new section starts from the old section it overlaps most (its style, scene and note), as when you split a section by hand, and ones that overlap nothing start blank. Running again replaces hand-edited sections with the tags' (the lyrics are the source).

**How the storyboard is requested** (`_call_json` in `backend/app/style_plan.py`): the API compiles a structured-output schema into a grammar and refuses one that is too big ("compiled grammar is too large"). The storyboard schema outgrew that with every outfit, hat, action and item, and trimming enums was not enough, so the storyboard and a scene redo no longer use structured output at all. The request tells Claude the JSON Schema in the prompt and Claude replies with a JSON object, which is found in the reply (a code fence or a sentence around it is fine), stripped of nulls and validated against the loose models (`LooseStoryboard`, `LooseRedo`). Those models take plain strings for every choice, the allowed words are listed in the instructions (`_vocabulary`, generated from the models so they never drift), and each choice is checked afterwards (`_one`: any case, spaces for underscores) with a default for a wrong word. A malformed or cut-off reply is a clear "try again" error. The style plan and a single section redo still use structured output; their schemas are small.

**Your direction is the main brief** (`directions_block` in `backend/app/style_plan.py`, `storyboard.py`, `illustrate.py`): the note you write for a section ("a river with a stone bridge at dawn") is put first in every request Claude gets for the style plan, the storyboard, a scene redo and a backdrop drawing, and the instructions say to follow it before anything else. You edit it right on the section's scene row (it is the same text as the note in the Sections panel); the scene's one-line description is now just *Claude's plan*, a read-only summary. From the direction Claude fills each scene's *Must show* list (`include`: the concrete things it names, which the backdrop painting must make clearly recognisable and large) and, for single objects the fixed props lack (a lighthouse, a pier), defines new custom objects and places them in the scene (`new_objects`; their art is drawn with *Draw art*, and a scene redo can add them too). Each scene remembers the direction it was planned from and each backdrop the one it was drawn from (`direction_used`, `art_direction`), so changing the direction shows *This direction has changed since…* with a one-click *Redo scene from direction* or *Redraw backdrop*. Nothing regenerates by itself: the text only takes effect when you press Generate, Regenerate or Draw. Scenes made before this show the marker wherever a direction exists, since there is no record of what they were made from.

**Camera direction** (`video/src/scenes/direction.ts`): in scenes the camera is directed from the lead character's action. Each scene is cut on downbeats into wide, medium and close shots (every bar in intense sections, every four in calm ones), starting wide and never repeating a kind back to back; kinds that would lose the figure (a jump, a dance) never go to a close-up. Shots push in slowly, each cut lands slightly punched in and settles, and a held sung word (a second or more) draws the camera toward the face. Untick *Auto-cuts* (next to *Visual mode*, a per-project setting) to keep each scene to one slowly pushing shot with no cuts. The section's own camera motion stacks on top, capped at 2.4x. Cast members wind up, ease from standing into their action and overshoot when a scene appears (`poseWithEntrance`, `easeAnticipate` in `easing.ts`; the dance's move changes each bar do the same, more subtly), and figures squash before each beat and stretch on it, scaled by loudness (`accent` in `actions.ts`).

**Flow between sections** (`video/src/timeline.ts`): each detected section change is moved onto the nearest downbeat (or beat), while sections you've edited cut exactly where you put them, and the transition is timed so its hit (the cut, the flash, the mask closing) lands on it, about two beats long. The incoming section starts drawing a little before the beat, both sections keep moving through the change, the palette blends from one to the next, and when the music builds into a change the outgoing section leans toward the camera. How much louder the music gets across the cut scales flashes and punches. Transitions: `crossfade`, `flash`, `zoomThrough`, `iris`, `dive`, `push` (slides the old section off), `whip` (a motion-blurred pan), `wipe` (an angled edge with a band of the foreground colour) and `punch` (punches in, then bursts the new section open with a starburst and a flash on the beat). By default the transition at each change is chosen from the music there (`chooseTransition`): a drop onto a hard hit gets a `punch`, or a `flash` after a build-up; rising energy a `whip` or `zoomThrough`; energy falling away a `dive` or `iris`; quiet or easing passages a `crossfade`; a steady stretch a `push` or `wipe`; never the same twice running. Set *Transitions* to *From the style plan* (a per-project setting) to use the plan's own `transition_in` per section instead.

**Motion blur** (*Motion blur* in the project's settings, Remotion only, off by default): each frame is drawn at 3 (*Light*, 180° shutter) or 5 (*Strong*, 270°) moments within the shutter and averaged (`shutterOffsets` in `MusicVideo.tsx`), so fast motion (a jump, a whip, a hand swing) smears while still frames stay sharp. Lyrics, the title, grain and audio are drawn once so text stays crisp. It multiplies the cost of every frame, in the preview and in the render, by the number of samples.

**Movement in scenes**: one camera state drives both the abstract visuals (a flat transform) and scenes, where it becomes parallax: each scenery layer has a depth from 0 (far) to 1 (the ground line), nearer layers pan and zoom more, and everything is drawn past the frame edges so no edge ever shows. `handheld` wanders on smooth noise and gets livelier with loudness. The world scrolls past a walking or running lead at exactly their stride (the walk cycle plants each foot and solves the legs with two-bone IK, `scenes/actions.ts`), so feet don't slide. Dancing follows the detected beats rather than the tempo and changes move each bar; jumps land on the beat with a crouch before take-off; heads, arms and long hair lag the body slightly (follow-through); figures breathe, squash and stretch, and nod to loud beats; and they cast contact shadows. Trees and grass sway in the wind, lamps swell on the beat, city windows change between bars, and fireflies or dust drift in some settings. Motion amplitudes follow smoothed loudness (`smoothed` in `features.ts`), not the raw per-frame value, so nothing jitters.

**Adding a visual preset**: add it to the `VisualPreset` literal in `backend/app/models.py`, run `npm run schema`, then add the component to `video/src/presets/` and register it in `presets/index.ts` and `presets/params.ts` (both are typed against the schema, so the build fails until they're complete).

## Troubleshooting

- **`ECONNREFUSED` in the web terminal**: the backend isn't running. Use `npm run dev`.
- **`401` from a Claude step**: enter your key under **Claude API key** at the top right, or fix it there if Anthropic rejected it. Keys are per browser, so each browser needs its own. Scripted calls need the header `X-Anthropic-Key: <key>`.
- **`409 another job is in progress`**: wait for the current analysis or render to finish.
- **Scripting the API**: POST/PUT/PATCH/DELETE need the header `X-MVM-Client: web` (otherwise `403`; this blocks other websites from writing to it), and only `localhost` / `127.0.0.1` are served (otherwise `400`). The `/docs` *Try it out* buttons can't add the header, so use e.g. `curl -H 'X-MVM-Client: web'`.
- **Render fails or fonts look wrong**: the first render needs internet to fetch Chrome, and fonts load from Google Fonts. Offline, text falls back to a system font. Check `projects/<id>/out/render.log`.
- **Beats or sections look off**: downbeats assume 4/4 with the first beat on the downbeat, and sections come from audio similarity. Fix the boundaries in the Sections panel (re-running analysis replaces your edits).
